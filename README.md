Это репозиторий проект. Kotlin для обеих платформ (Android и Backend)

🏗 Архитектура проекта

Проект реализован как модульный монорепозиторий.
Модули:

    :shared — «Единый источник истины». Здесь лежат общие DTO (модели данных), константы API, правила валидации и Enum'ы. Всё, что здесь написано, доступно и серверу, и мобилке.

    :server — Бэкенд на Ktor. Реализует REST API, работает с базой данных и авторизацией.

    :app — Android-приложение. типо Clean Architecture (если хотите поменять скажите):

        data: Реализация репозиториев, работа с сетью и БД.

        domain: Бизнес-логика, UseCases и сущности.

        presentation: UI на Jetpack Compose и ViewModels.

ВАЖНО:

    libs.versions.toml — Центральный каталог зависимостей. Все версии библиотек меняются ТОЛЬКО здесь.

    build.gradle.kts :main — Если добавите плагин сначало киньте сюда через apply false.

🛠 Технологический стек (Android)

Для работы в Android-модуле я хочу импользовать:

    Room — Локальная БД.

    Retrofit — для API.

    Koin — Инжектор.

        Почему Koin? Вместо Dagger/Hilt, чтобы не тратить время на долгую кодогенерацию (Koin работает в Runtime, что значительно ускоряет сборку проекта в процессе разработки) и еще он легче.

🔄 Git Flow

Классическая схема Git Flow:

    main — Стабильная ветка. Сюда ничего не коммитим напрямую.

    dev - для всего более менее готового.

    feature/название-фичи — Отводим ветку от dev для каждой задачи.

    Merge Requests — Любой код попадает в общую ветку только через общюю проверку.

📈 Идеи для аналитической части:

    Проектирование метрик: Нужно что-то трекать? (например, "время создания задачи", "процент выполненных задач за день").

    Мониторинг стабильности: Настройка Sentry или Crashlytics для отслеживания ошибок как на сервере, так и в приложении.

    Backend Metrics: Можно поднять Micrometer или встроенные метрики Ktor, чтобы анализировать нагрузку на API и время ответа базы данных.
